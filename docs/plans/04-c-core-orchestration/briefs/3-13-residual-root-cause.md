## The question (Cody HARD rule: no spool pin without understanding why)

3-12 attributed ~15.1 M rows to spool on the ground that sentinel `background`/`background_boundary` failures are encoder clip-connector vertices on leaf edges produced by crossing spool rings. The review accepts the counts and the invalidity witness but not the cause: only 2 of 70,999 source rings were counterfactually repaired; the crossing predicate is necessary not sufficient (4-73 % failure by ring size); the failing vertices lie on leaf edges 2,000-4,000 raw outside the producer's bounding box. It could be (spool) an open chain closed by an extractor chord, (build) the encoder's polygon clipping producing wrong connector geometry for self-crossing rings where an exact even-odd clip would NOT, or (checker) K1 demanding an outline near a legitimate clip-edge vertex. Decide which, per stratum, with a witness and a counterfactual.

## Required work

1. **Exact-clip oracle (the discriminator).** For a random sample of ≥ 300 failing groups per (kind, level, type, sentinel) stratum (independent of Sol's predicate, fixed seeds recorded), compute with exact arithmetic (integer raw lattice; the K1 `inside` rule: even-odd over all same-type level shapes) the region `R = even-odd(spool rings of that type) ∩ leaf frame` and compare to the disc pieces of that leaf (decoded by D1). Report per group: does the disc piece set equal R (same area symmetric difference, vertices within tolerance)? If the disc differs from the exact clip → the encoder/clipper is wrong for that ring (build cause candidate; locate file:function in `parser/kiwiw/_e2.c`/`_cenc.c`/clip code). If the disc equals R and R's boundary includes the connector (the even-odd region really has that edge) → the vertex is on the region boundary: then why is it farther than 0.500001 from a same-type OUTLINE (spool defect: the region boundary has no outline there) vs K1 rule too strict at clip edges (checker). Use `docs/plans/03-map-layer-parity-remediation/briefs/3C-04-roundtrip-redesign.md` and `parser/tools/quantisation_roundtrip.py` for the rule as written; "boundary vertices on the leaf/frame edge" handling is explicitly in scope.
2. **Why only some crossing rings fail (Condition C).** Take matched pairs (failing vs non-failing crossing rings of similar size/type in the same level) and find the separating property (e.g. winding, which side the closing chord is on, whether the chord crosses a leaf boundary, ring orientation, repeated vertices, ring-over-leaf count). State it as a predicate in dump/side-table columns with a measurement story, and validate on a held-out sample.
3. **Complete-repair counterfactual per stratum (Condition A).** For every stratum (L0 288, 291, 289, 578; L2 289; L6 288; both kinds) build a windowed counterfactual disc (serial, -j4) where ALL source rings the predicate names are repaired by the MINIMAL change the hypothesised mechanism implies (or removed, if no repair is defined: say which), and report the failures remaining for that stratum (zero required for attribution). Strata without a complete counterfactual are NOT attributed: they go back to `unattributed` in the rules file.
4. **Near-threshold rows (Condition B).** The 2,184 fill and 12,818 boundary new rows within 0.5-1.0 raw of an outline: test whether they are a tolerance/quantisation effect (disc vertex rounding vs outline) or the same mechanism; no tolerance change merely to reduce a count; a tolerance change needs a recorded cause and a measured gap.
5. Classify honestly: each group ends as `spool` (counterfactual proves it), `build` (disc differs from the build's own rule; give the fix location, the rows it must move to 0, and the witness path), `checker` (give the K1 rule/window/tolerance and what the Python oracle does at that point, lockstep fix needed), or `unattributed`. If the same mechanism is both (a defective spool ring AND a build that mishandles such rings badly), classify by what the fix would be: a build that can handle a self-crossing even-odd ring correctly but does not is a `build` cause; a ring that is not a polygon (open chain closed by a chord) with no defined correct output is `spool`. Argue it with the exact-clip oracle, do not assume.
6. Update `rules_bg.json`; re-run `k1_triage.py classify` (heavy, under lock) on the extended dump; report the partition per cause class per kind and the remainder per (kind, level, type). Document any side tables in `docs/provenance.md`.
