# Completeness root cause

## Intent

Cody's standing rule (2026-10-05, hard): Maps is complete only when end-to-end generation matches the original DVD in every aspect that can be verified, every claim, assumption, and implementation aspect is verified and proven, and there are no unexplained deviations — each has a root cause.

Maps Manager asked Design to produce the next design so the lane can move again. The open remainder is the still-unattributed completeness failures after 3-15 / 3-16 / 3-17. Prove root causes from R vs G vs spool evidence; never close a row by relabelling. Land each phase on master. No feature branch. No pull request. Do not reseat 170, 3-16, or 3-17. Do not draw plan 04 phases 4–6 or plan 06.

## Solution shape

Prove, row by row, why each currently unattributed completeness failure exists, using original-disc bytes, generated bytes, spool witnesses, and checker/rules logic. Then either fix the proven defect class or document a proven non-deviation. Relabelling (`O07`, `checker:repaired-not-representable`, or any new cause string without a reproducer) is forbidden as a close.

### Domain: completeness evidence

- Owns: the live failing completeness set on the disc in force, and the per-row comparison of original DVD (R) bytes / decoded type presence against generated (G) for those identities, plus the spool/K1 requirement witness already used by classify.
- Contract: every failing completeness identity on the disc in force appears once in a committed evidence table with: full native key, classify assignment (rule id or `NO_RULE`), membership in the recorded 188 and 89 sets, R witness path, G witness path, and spool/requirement witness path. Counts of failing / attributed / unattributed are stated, and any drift from 3-17's 776·308 and 3-15's 274 is named. Disc sha is `4ed9cd80…` or a recorded successor re-oracle.
- Non-goals: no reseat of 3-16 or 3-17 science packets; no design-170 padding work; no plan 04 phases 4–6; no plan 06; no new roles or trials; no full Phase 3 close (name_anchor pin, 3-90 gates, and other kinds stay outside).

### Domain: cause groups

- Owns: partitioning the **unattributed** rows from the evidence table into groups, each closed only by a reproducer that isolates one mechanism and predicts a count movement.
- Contract: every unattributed row is either in exactly one proven group (reproducer + expected movement recorded) or listed as a named open question with the failed discriminators tried. A science label without a reproducer is not a group close.
- Non-goals: no catch-all rule; no registering a new `cause`/`where` without the reproducer; no treating 3-16's negative EO-stitch result as a positive cause.

### Domain: fix or proven non-deviation

- Owns: applying the Phase 3 cause taxonomy already signed in plan 04 — checker → fix checker (sha unchanged); build → fix C and record re-oracle; spool → enumerate by item identity for the successor list; proven non-deviation → G matches R for that cell/type under the named contract, with byte evidence.
- Contract: for each proven group, either the predicted count movement is observed on the disc in force after the fix, or the non-deviation byte proof is committed. Unproven rows stay open questions. Disc sha moves only by recorded re-oracle.
- Non-goals: no tolerance loosen without a recorded cause; no closing plan 04 Phase 3 from this plan alone; no editing S02–S05 or O01–O06 predicates except where a reproducer of this plan proves a specific rule is wrong.

## Decisions

1. Plan number is **14**. Plans 11–13 are already closed records on master.
2. Land on master directly. No feature branch. No pull request.
3. Three phases, one coding worker each. Refine is per phase only if that phase's approach is open.
4. 3-15, 3-16, and 3-17 recorded results are inputs. Do not reseat them. Do not reseat design 170.
5. `checker:repaired-not-representable` and any O07 candidate stay non-causes until a Phase 2 reproducer proves them.
6. This plan addresses the completeness unattributed remainder only. It does not draw plan 04 phases 4–6, does not author plan 06, and does not claim Phase 3 closed.
7. Verify every count against files on master or by read-only checkers in a throwaway worktree. Never trust a commit message alone (void plan-10 lesson).

- Answer chosen: yes — use the paths recorded in `docs/provenance.md` for scratch-3-14 / 3-17 (read-only), or an identical-sha copy. Phase 1 may rebuild only the classify/evidence artefacts under a new scratch dir.

### Assumption 2

- Question: is the live unattributed set still the 3-17 remainder (188 historic still `NO_RULE`, plus the rest of the raw 308 / corrected 274), or have plans 08–13 changed it?
- Answer chosen: treat 3-17 as the last live classify; Phase 1 re-measures and designs onward from what master actually shows. Plans 08–13 did not edit completeness rules or dumps.
- Rationale: closed plan records and `docs/design/k1-triage.md` say those plans do not establish completeness attribution.
- If wrong: Phase 1 names the drift; later phases use the live set, not the stale 274/308 figures.

### Assumption 3

- Question: does “compare disc bytes with generated bytes” mean R vs G for each unattributed completeness cell/type, in addition to the spool/K1 witness?
- Answer chosen: yes. Standing rule is DVD parity. Completeness failures are spool-vs-G today; the evidence table must also show whether R emits that type in that cell so a later cause can distinguish checker-over-demand, build defect, and true G≠R deviation.
- Rationale: Cody's hard rule requires every verifiable aspect match the original DVD and every deviation have a root cause.
- If wrong: Cody narrows Phase 1 to spool-vs-G only; the R column becomes optional.

### Assumption 4

- Question: can this plan close plan 04 Phase 3?
- Answer chosen: no. Completeness attribution is necessary but not sufficient (name_anchor spool pin, 3-90 PSS/`wall_s`/join/review blockers, and any remaining kinds stay).
- Rationale: OVERVIEW and the 3-90 record list those blockers separately; this design must not invent Phase 3 close.
- If wrong: Cody widens scope; do not silently absorb 3-90 into these phases.

### Assumption 5

- Question: may a Phase 2 group inherit the 3-15 complete-repair science as its reproducer?
- Answer chosen: no. That science may be **cited** as prior measurement. A group closes only when this plan's worker re-runs or packages a reproducer that predicts a live count movement (or a concrete R/G byte equality) under one mechanism.
- Rationale: the user forbids closing by relabel; 3-15 itself refused to register O07.
- If wrong: Cody accepts the existing 3-15 harness as the Phase 2 reproducer for the 188 without re-run; still requires a registered rule or checker fix in Phase 3, not a label alone.

1. After Phase 1, do the live unattributed rows equal the union of the recorded 188 and the 89, a subset, or a larger set (raw 308 vs corrected 274)? **Phase 1 answers.**
2. For rows where R and G both lack the required type, is the standing-rule deviation absent (checker-only) or still a spool/G contract issue? **Phase 1/2 answer per row.**

## Phases

### Phase 1 — Per-row evidence table for every live unattributed completeness row

- Outcome: on the disc in force (`4ed9cd80…` or a recorded successor), a committed evidence table lists every currently failing completeness identity exactly once. Each row has full native key, classify assignment (O01/O04/O05/O06/`NO_RULE`/other), flags `in_historic_188` and `in_added_89` against the committed 3-17 table and 3-16 TSV, an R byte/decode witness, a G byte/decode witness, and a spool/K1 requirement witness (or an explicit `evidence gap` open question for that column). The table header states: failing total, attributed by rule, unattributed total, and the numeric drift vs 3-17 (776 failing, 308 unclassified) and 3-15 (274 unattributed). No cause is named. No rule file is edited. 3-16 / 3-17 / design-170 files are not rewritten.
- Surfaces: new triage record under `docs/plans/14-completeness-root-cause/` (evidence TSV + short note), read-only use of `parser/tools/k1_triage.py classify` and existing dump/disc paths; `docs/provenance.md` scratch entry for new evidence only.
- Approach: known
- Depends on: master tip containing 3-17 and plans 08–13; disc sha gate as Assumption 1.
- Refine: skipped if the dump+classify path is unchanged; otherwise a short refine for the R-fetch helper only.

### Phase 2 — Root-cause groups, each closed by a reproducer

- Outcome: every Phase 1 unattributed row is either (a) member of exactly one named group whose committed reproducer isolates a single mechanism and states the expected completeness count movement (or expected R/G byte equality), or (b) listed under `open questions` with the discriminators tried and why none proved. Groups that merely restate `checker:repaired-not-representable` or “EO-stitch side-effect” without a new positive reproducer are rejected. The 3-16 negative result may be cited to exclude the already-failed EO-stitch bypass; it does not close a group by itself. No rule registration and no encoder/checker edit in this phase.
- Surfaces: group note + reproducer scripts under the plan-14 scratch/triage paths; may read `_k1_cmp.c` / `_cenc.c` / spool forensics read-only.
- Approach: open
- Depends on: Phase 1 evidence table.
- Refine: required (approach open). Divergent candidates are scored only against the Phase 2 outcome above.

### Phase 3 — Fix or proven non-deviation per group

- Outcome: for each Phase 2 proven group, exactly one of the following is true and evidenced on the disc in force: (1) **checker** — checker change lands, predicted unattributed rows leave the failing set, build sha unchanged; (2) **build** — C fix lands, predicted rows leave or change as stated, re-oracle recorded with changed cells; (3) **spool** — item identities appended to the enumerated spool-caused list for the successor design, still failing under live rules; (4) **proven non-deviation** — R and G byte/decode witnesses agree for that cell/type under the named contract, and the checker demand is shown inapplicable without loosening an unrelated tolerance. Any row still lacking (1)–(4) remains a named open question. Live completeness unattributed count equals the open-question count (ideally 0). O01–O06 predicates change only when a Phase 2 reproducer proves that specific rule wrong. Plan 04 Phase 3 is **not** marked closed by this phase alone.
- Surfaces: `_k1_cmp.c` and/or `_cenc.c` only as the proven group requires; `docs/plans/04-c-core-orchestration/triage/rules_other.json` only for a rule whose reproducer is Phase 2-proven; plan-14 close-out record; tests under `parser/tests/` for the moved count or byte gate.
- Approach: known once Phase 2 groups exist; each group is one worker landing on master.
- Depends on: Phase 2.
- Refine: skipped per group when the reproducer already names the fix site; otherwise refine that group only.
